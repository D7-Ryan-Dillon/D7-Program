# V4: the second set of fifteen tiles

Fifteen coordinated engine-7 recipes, one per typology (Gathering, Workspace, Lobby; five each), named `<category>_<n>_<typology>_v4`. The concept, the design matrix, the pictures, the evaluation and the assembly results are in **`docs/TILE_SET_V4.md`**; the conventions for whoever writes the next set are in the V4 section of **`docs/RECIPE_AUTHORING.md`**.

| File | What it is |
|---|---|
| `kit4.py` | the kit: `pod` (a vertical void), `Ports` (the standard 6 x 8 ft doorway with a retained frame; `slope=` tilts the tunnel for a ramp), `stair_path` / `ring_ramp` / `ramp_pods` (real stairs and ramps; solid wedges with headroom pods), `L_plan`, `box_container`, `container_xy`, `ground_field`, `poche`, `trim`, ... |
| `defs_g.py`, `defs_o.py`, `defs_l.py`, `defs.py` | one function per tile (the docstring is the concept) and the table `TILES` |
| `build.py [G1 O3 ...]` | writes `recipes/<name>.recipe.json`, runs the real engine headless, exports to `C:/tmp/tiles4/<name>/` (a short path: Windows 260 character limit), draws the section sheet |
| `verify.py` | rebuilds each stored recipe from the file alone: `RECIPE CHECK: OK`, at most 24 sources, under 32,000 characters, metadata matches the name |
| `view4.py`, `iso.py`, `overview.py`, `render_assemblies.py` | the walking sheet, isometric cutaways, the 3 x 5 overview, the assembly pictures |
| `package.py` | one import-ready `_analysis` zip per tile, the `_reference` zips, the whole set in one zip, `SET.json` (written to `package/`, git-ignored) |
| `lab_pod.py`, `lab_door.py` | calibration labs: what a pod or a door tunnel really cuts for a given spread, dose and depth |
| `recipes/` | the fifteen recipes, `previews/` (sections, walking sheets, isometric cutaways, `V4_overview_3x5.png`) |
| `assemblies/` | the output of `npm run check:v4`: `results.txt` and pictures of automatic assemblies, nests and vertical meetings |
| `EVALUATION.md` | the app's own table of the set (generated by `npx tsx scripts/v4/table.ts`) |

Run with Rhino's bundled Python 3.9 and its site-envs on `PYTHONPATH` (see `engine/headless/run_headless.py`):

```
python engine/tiles/v4/build.py            all fifteen (about a minute each); or  build.py G5 O4
python engine/tiles/v4/verify.py           the rebuild check
python engine/tiles/make_fixtures.py C:/tmp/tiles4 lib/tiles/fixtures-v4     then  npm run check:parity
npm run check:v4                           the assembly evidence
python engine/tiles/v4/iso.py --all ; python engine/tiles/v4/overview.py ; python engine/tiles/v4/render_assemblies.py
python engine/tiles/v4/package.py
```

The first set (`engine/tiles/recipes`) is unchanged: ground slab top at z = 2 ft and mid datum at z = 12 ft. V4 uses z = 1, 11, 21, 31 ft; do not copy a number from one set's recipes into the other without checking its datum.
